# Who Ate My Cheesecake?

> 하우스메이트 여섯이 사는 집. 어젯밤 냉장고의 치즈케이크가 사라졌다.
> 플레이어는 여섯 중 한 명이 되어 나머지 다섯을 자유롭게 심문하며 범인을 찾는다.
>
> **SPUM 웹엔진**이 캐릭터와 맵을 그리고, **SAM(LLM)**이 그 캐릭터들의 입으로 말한다.
> 이 문서는 그 둘을 실제로 어떻게 붙였는지 구현 과정을 설명한다.

---

## 1. 실행하기

```bash
node spum/serve.mjs
```

브라우저에서 **http://127.0.0.1:8790/spum/play.html** 을 연다. 별도 빌드·설치 과정 없음 —
`package.json` 의 런타임 의존성이 0개라 `node` 만 있으면 뜬다. `.env` 에 SAM 키를 넣으면 실제
LLM 응답이, 없으면 로그인 다리(§6) 또는 간이 폴백이 붙는다.

조작·플레이 방법은 [WHO_ATE_MY_CHEESECAKE_GAME_GUIDE_KO.md](WHO_ATE_MY_CHEESECAKE_GAME_GUIDE_KO.md) 에 따로 정리했다. 이 문서는 **어떻게 만들었는지**만 다룬다.

---

## 2. 무엇을 만들었나

- **NPC 6명** — 각자 나이·직업·MBTI·생활 루틴·관심사·민감한 부분·서로 다른 관계를 가진다. 플레이어가 그중 하나를 골라 Player가 되고, 나머지 다섯이 AI NPC가 된다.
- **자연어 대화** — 정해진 선택지가 아니라 플레이어가 직접 문장을 친다. NPC는 SAM이 그 순간 새로 지어낸 문장으로 답한다.
- **기억과 소문** — NPC는 대화 문맥을 유지하고, 서로 마주치면 아는 것을 조각으로 주고받는다. 출처가 항상 붙는다("루비 말로는 코코가 23시에 부엌에 있었대").
- **추리 게임 루프** — 알리바이·거짓 방패·공범의 거짓 목격이라는 세 종류의 거짓말만 존재하고, 플레이어는 대화 예산 18회 안에 범인·시각·목격자를 지목한다.

핵심 설계 원칙 하나: **사실은 게임 엔진이 소유하고, 말은 SAM이 짓는다.** SAM은 시각·장소·목격 같은 객관적 사실을 절대 스스로 결정하지 않는다. 왜 이 분리가 필요한지는 [DIALOGUE_SYSTEM.md](DIALOGUE_SYSTEM.md) §21에 자세히 있다.

## 3. 아키텍처

```
플레이어 입력 (한국어 문장)
        │
        ▼
classifyIntent()          — 화행 분류: 질문인가? 목격을 묻나? 후속 질문인가?
        │                    (spum/dialogue.mjs)
        ▼
knowledgeOf() / factSheet() — "이 NPC가 실제로 아는 것"만 카드로 뽑는다
        │                    (spum/round.mjs, spum/dialogue.mjs)
        ▼
buildMessages()            — 캐릭터 정체성 + 사실 카드 + 관계 + 최근 6턴 맥락
        │                    을 합쳐 SAM 프롬프트를 만든다
        ▼
        SAM (LLM)          — 자연스러운 대사를 짓는다
        │
        ▼
violations()                — 지어낸 시각·장소·인물이 없는지 문장을 검사한다
        │                    (spum/dialogue.mjs)
        ▼
   출력 or 재생성
        │
        ▼
remember() / gossipOnce()   — 대화 결과를 기억에 남기고, NPC끼리 마주치면 전파한다
                              (spum/memory.mjs)
```

세 계층으로 나뉜다.

| 계층 | 파일 | 소유하는 것 |
|---|---|---|
| **사실** | `spum/round.mjs` | 시드로 재현 가능한 판 하나: 여섯 명의 동선, 범인, 범행 시각, 거짓말 3종 |
| **기억** | `spum/memory.mjs` | 누가 무엇을 언제부터 어떤 출처로 알게 됐는가 |
| **대사** | `spum/dialogue.mjs` | 위 둘을 SAM 프롬프트로 조립하고, SAM 응답을 검증 |

세 파일 모두 프레임워크 없는 순수 ES 모듈이다. 게임 화면(`spum/play.html`)은 SPUM 런타임에
캐릭터·타일맵을 위임하고, 자체 캔버스는 말풍선·이름표 오버레이만 그린다.

## 4. 사실 생성 — `round.mjs`

한 판(`makeRound(seed, playerId)`)은 다음을 결정론적으로 만든다.

1. **동선** — 여섯 명이 21시~02시 여섯 시간 동안 8개 방 중 한 곳씩에 있다. 같은 방·같은 시각이면 서로 "목격"한 것이다. 이게 목격의 전부다 — 별도 시야 계산이 없다.
2. **범행** — 범인이 부엌에 **혼자** 있던 시각을 범행 시각으로 고른다. 그런 시각이 우연히 없으면 범인의 동선 한 칸을 부엌으로 밀어 넣어 만든다(그렇지 않으면 "잘 돌아다니는" 캐릭터만 범인으로 뽑히는 편향이 생긴다).
3. **거짓말 3종만 존재**
   - 여섯 모두 "안 먹은 이유"(방패)를 하나씩 갖고, 55% 확률로 참이다. 거짓 방패는 반드시 그걸 깰 실마리(그 사람을 실제로 본 목격자)를 판 안에 하나 심는다 — 아니면 그 판은 버리고 다시 만든다(`round.mjs:138-140`).
   - 범인은 범행 시각의 진짜 자리를 절대 말하지 않고, 대신 "그 시각엔 딴 방에 있었다"는 알리바이 거짓말을 민다.
   - 조건이 맞으면(범인과 단둘이 마주친 시각이 있고, 그 방을 정직하게 목격할 사람이 있으면) 공범 하나가 거짓 목격을 대신 증언한다.
4. **재시도 루프** — 위 조건을 만족하는 판이 나올 때까지 최대 400번 다시 굴린다(`for (let attempt = 0; attempt < 400; attempt++)`). 순수 함수라 같은 시드는 같은 판을 낸다 — 회귀 테스트(`spum/roundtest.mjs`, `harness.mjs`)가 여기 의존한다.

SAM은 이 단계에 전혀 관여하지 않는다. `knowledgeOf(round, id)` 가 "이 사람이 실제로 아는 것"만
뽑아 주고, 그 밖의 시각·장소·인물은 뒤에서 `violations()` 가 걸러낸다.

## 5. 기억과 소문 — `memory.mjs`

기억은 대화 기록의 복사가 아니라 **조각(`entry`)의 집합**이다. 조각은 `own`(자기 자리) ·
`seen`(직접 목격) · `place`(전해 들은 자리) · `clue`(전해 들은 사정) · `asked`(누가 무엇을
캐고 다니는지) 등 몇 종류뿐이고, 같은 내용을 다시 들으면 새 조각을 만드는 대신 **출처만
추가**한다(`remember()`).

```js
// 같은 사실이라도 출처가 다르면 값이 있다
const had = memTo.byKey.get(keyOf(e));
if (had) { (e.from || []).forEach(f => { if (!had.from.includes(f)) had.from.push(f); }); return null; }
```

소문 전파(`gossipOnce`)는 두 NPC가 근접했을 때 한쪽이 상대가 모르는 조각 하나를 골라
넘긴다. 이때 **직접 경험과 전언을 문장에서부터 구분**한다 — `describe()`/`gossipLine()`이
`own`(직접)과 `place`(전해 들음)에 서로 다른 어미를 붙인다: "나 21시엔 거실에 있었어" vs
"루비 말로는, 코코가 23시에 부엌에 있었대". 범인은 자기 범행 시각 조각을
`shareables()` 에서 제외해 절대 흘리지 않는다.

기억 상한은 48개(`CAP`)고, 넘치면 판 시작 때 심어진 씨앗(`seeded: true`)이 아닌 것부터
오래된 순으로 버린다. "모든 것을 영원히 기억"하지 않고 지금 대화에 의미 있는 것만 남기려는
설계다.

동네 사람(`VILLAGERS`)은 사건 당사자가 아니라서 씨앗이 없는 빈 기억(`createBlankMemory`)에서
시작한다 — 오직 하우스메이트와 마주쳐야만 뜬소문을 얻는다. 이 구조 덕분에 소문 전파가
하우스메이트 사이로 한정되지 않고 동네 전체로 자연스럽게 번진다.

## 6. SAM 프롬프트 조립과 검증 — `dialogue.mjs`

### 화행 분류

`classifyIntent(text)` 는 정규식 기반으로 플레이어 발화를 `ASK_EATEN` / `ASK_SIGHTING` /
`ASK_ABOUT` / `ASK_WHEREABOUTS` / `FOLLOW_UP` / `GREET` / `SOCIAL` / `UNKNOWN` 으로 분류한다.
한국어 구어체 변형("먹었", "먹었어", "먹은 거", "혹시 먹" 등)을 패턴 수준에서 흡수한다.
이 분류는 SAM을 대신하지 않는다 — SAM이 처리해야 할 발화의 성격을 프롬프트 힌트
(`actHint`)로 넘겨주는 보조 계층일 뿐이다.

### 프롬프트

`buildMessages()` 가 한 번의 SAM 호출에 넣는 것:

- 세계관 텍스트(`premise.json` 의 `world`)
- 캐릭터 정체성 — SPUM Cast의 `mbti`, 성격 경향, 말투 예문(few-shot). **개인사·사건 정보는
  넣지 않는다** — 예문은 말의 결만 보여줘야 한다는 원칙(CHARACTER_SYSTEM.md §13)을 그대로 코드로 옮긴 것.
- `factSheet()` — 이 NPC가 실제로 아는 것만 뽑은 카드. 범인이면 알리바이 거짓말 지침이,
  공범이면 심어진 거짓 목격 지침이 여기 추가된다.
- 상대(플레이어)와의 관계 한 줄(`relationLine`)
- 최근 6턴 대화 맥락(`history.slice(-6)`) — 문맥 연속성의 핵심
- 응답 길이 가이드 — 캐릭터 성향(`talkative`/`moderate`/`reserved`)에 따라 문장 수를 다르게 지시

### 검증

SAM이 문장을 뱉었다고 바로 내보내지 않는다. `violations()` 가 그 문장 안의 "시각+방" 짝과
"이름+목격 동사" 조합을 이 NPC의 화이트리스트(`knowledgeOf` + 전해 들은 것)와 대조한다.

가장 까다로웠던 부분은 **한 문장에 여러 시각이 나올 때 어느 시각과 어느 방이 짝인지**
정하는 것이었다. 처음엔 문장 안의 시각 N개 × 방 N개를 전부 곱해서 검사했더니, 승인된 두
쌍을 한 문장에 같이 말하기만 해도("21시엔 텃밭, 22시엔 거실이었어") 존재하지 않는 교차
조합("21시,거실")까지 위반으로 오탐했다. 시각 등장 위치를 경계로 문장을 구간
나누는 방식(`hs[idx].i` 부터 다음 시각 등장 전까지)으로 바꿔서, 500판 표본 기준
참인 문장 오탐 0% · 실제 알리바이 거짓말 탐지 100%를 확인했다(`round.mjs`/`dialogue.mjs`의
`violations()` 주석 및 `harness.mjs` 참고).

## 7. 실제로 부딪힌 문제들

- **SPUM 런타임이 모델 자리에 등급 이름을 보낸다.** `{"model":"medium"}` 을 그대로 SAM에
  넘기면 `Unknown model` 404가 난다. `spum/serve.mjs` 의 `SAM_TIER` 매핑에서 등급을 실제
  SAM 모델 이름으로 바꿔치기한다.
- **로그인 세션이 30분쯤에 만료된다.** 서버 저장이 조용히 끊기는데 화면은 멀쩡해 보여서
  한참 뒤에야 알아챈다 — 자세한 함정 목록은 [CLAUDE.md](CLAUDE.md) 에 정리했다.
- **AI로 생성한 맵의 통행 판정.** 그림만으로 벽/문을 구분하는 시도는 전부 실패했고,
  결국 걸어 다닐 수 있는 칸의 최대 덩어리를 찾아 고립된 방마다 가장 얇은 벽 한 칸을 뚫는
  방식으로 해결했다(CLAUDE.md §9).
- **화행 검증의 오탐/미탐 트레이드오프**는 위 §6에 정리한 그대로다.

이 프로젝트 작업 중 반복해서 얻은 함정과 그 근거는 전부 [CLAUDE.md](CLAUDE.md) 에 신뢰도
표기(★~★★★★★)와 함께 남겨 뒀다 — SPUM Studio를 다시 만질 일이 있다면 그쪽을 먼저 본다.

## 8. 파일 지도

| 파일 | 역할 |
|---|---|
| `spum/round.mjs` | 판 생성 — 동선·범인·거짓말 3종을 결정론적으로 만든다 |
| `spum/memory.mjs` | NPC별 기억, 소문 전파, 출처 관리 |
| `spum/dialogue.mjs` | 화행 분류, SAM 프롬프트 조립, 응답 검증 |
| `spum/serve.mjs` | 정적 서빙 + SAM 프록시(키는 서버에만) + 로그인 다리 |
| `spum/play.html` | 게임 화면 — SPUM 런타임에 렌더링 위임, UI 오버레이만 직접 그림 |
| `CHARACTER_SYSTEM.md` | 캐릭터 설계 철학 — 왜 서사를 최소화하는가 |
| `DIALOGUE_SYSTEM.md` | 대화 시스템 설계 철학 — 화행·기억·출처·검증의 원칙 |
| `WHO_ATE_MY_CHEESECAKE_GAME_GUIDE_KO.md` | 플레이어용 조작 설명서 |
| `CLAUDE.md` | SPUM Studio/SAM 작업하며 부딪힌 함정 모음 |

설계 철학(왜 이렇게 만들었나)은 `CHARACTER_SYSTEM.md`/`DIALOGUE_SYSTEM.md`에, 실제 구현
증거는 이 문서에 있다. 두 문서는 서로를 보완한다.
